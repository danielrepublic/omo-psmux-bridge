Harness note (not a bridge defect)
----------------------------------
An earlier run isolated the session under `-L te2f`. OmO's plugin then aborted
the layout: `list-panes -t <session>:0` and `select-layout -t <session>:0`
exited 1, because a client without -L cannot resolve a session target inside a
namespaced server (port file is `<ns>__<session>`), while pane-id targets
resolve via the current server. `#{session_name}` is the bare session name, so
the plugin's targets do not carry the namespace. Re-running in the default
namespace (above) passes end to end. The bridge forwards exactly what OmO
emits; this is an OmO-under-namespace limitation, recorded so future E2E runs
use the default namespace.
