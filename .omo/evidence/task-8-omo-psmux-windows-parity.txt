  ISOLATION -- how, and why not `-L`
  The task asked for `-L <namespace>` on every invocation.  For the BARE
  invocation that is impossible by construction, and the reason is in the launcher:
  psmux.cmd rewrites an EMPTY argv to `new -A -s default`, and classifies ANY
  non-empty argv as pass-through.  So `psmux.cmd -L ns ...` is not the bare case
  at all -- it is a different classification.  Measured facts, all verified:
    * `TMUX_TMPDIR` does not exist in psmux 3.3.8.  String search of psmux.exe:
      'TMUX_TMPDIR' at offset -1, 'TMPDIR' at offset -1.  So an environment
      variable cannot isolate a zero-argument call either.
    * `-L <ns>` IS supported and DOES isolate.  Server command line carries it:
        "psmux.exe" server -s <name> -L omo_p8nsX
      and `list-sessions -L ns` saw a session that plain `list-sessions` did not.
      Sockets are TCP listeners on 127.0.0.1:<port>; state lives in
      C:\Users\Daniel\.psmux.
    * `PSMUX_DATA_DIR` is a real psmux environment variable (found in psmux.exe;
      the --help ENVIRONMENT VARIABLES block does not document it).
  So checks 2 and 3 were each run TWICE:
    (a) `-L` form: psmux.cmd -L omo_p8nsF new -A -s default -- a pass-through of
        byte-for-byte the command line the bare form expands to, strictly
        namespaced.  Pane path == D from D, and still == D from E.
    (b) TRUE bare form: psmux.cmd with zero arguments, isolated by pointing
        PSMUX_DATA_DIR at a throwaway data dir, so the real default socket and
        the real ~/.psmux were never written.  Real socket verified NONE before
        and NONE after.
  Sections 2 and 3 report (b), the real daily flow, with (a) as corroboration.
  One run did briefly exercise the bare form on the real default socket, before
  PSMUX_DATA_DIR had been discovered; the world was verifiably empty then (0 psmux
  processes, 0 sessions) and the default socket was verified empty again
  afterwards.  Its residue is accounted for below.
