DEFECT 1 — `(fail) -- insertion > the emitted respawn argv is verb, flags, `--`,
command line — nothing after`
Symptom: `error: expect(received).toHaveLength(expected)  Expected length: 5
Received length: 6` at test/translate.test.ts:444.

ROOT CAUSE: an off-by-one in the test's own expectation, self-contradictory
within its own body. The test fed `["respawn-pane","-k","-t","%7", AT_PLAIN]`
(5 input elements) and asserted BOTH:
    expect(translation.argv).toHaveLength(5);   <-- contradicted the six below
    expect(translation.argv[0]).toBe("respawn-pane");
    expect(translation.argv[1]).toBe("-k");
    expect(translation.argv[2]).toBe("-t");
    expect(translation.argv[3]).toBe("%7");
    expect(translation.argv[4]).toBe("--");
    expect(translation.argv[5]).toBe(translation.helperCommandLine);
An assertion on index 5 REQUIRES six elements. The literal 5 was the only
inconsistent statement in the test.

THE ARITHMETIC, against CONTRACT.md 7.1 (`src/server/connection.rs:2102-2103`:
the respawn command is read only from `args.iter().position(|a| *a == "--")`
then `args[i+1..].join(" ")`):
  * The payload element is REPLACED one-for-one by the command operand. One
    element in, one element out: the count does not change.
  * `--` is INSERTED, not substituted. +1 element.
  => verb, -k, -t, %7, --, command line = SIX. Which is what src/translate.ts
     emits (`[verb, ...flags, ...(dashDash ? ["--"] : []), commandLine]`,
     src/translate.ts:258).

VERDICT: FIXED THE TEST, NOT THE IMPLEMENTATION. The implementation was already
correct on every clause of the contract — `--` immediately before the operand,
nothing after it — and the suite's other, stronger assertions independently
confirm it and were passing before this fix:
  * test/translate.test.ts:415 `argv[argv.length - 2] === "--"` — PASSED before.
  * test/translate.test.ts:926-935 the `--` tail is exactly ONE element — PASSED.
  * test/translate.test.ts:459-466 head is exactly `[verb, ...flags]` — PASSED.
Relaxing the length to match output was NOT an option and was not done; the
assertion was made STRONGER, not weaker: it now pins the whole array by
deep-equality against a literal, and additionally asserts the command line is
the last element (`at(-1)`), that `--` sits at index 4, and that
`slice(-2,-1)` is `["--"]`.

8. MUST-NOT-VIOLATE CHECKLIST — HOW EACH INVARIANT IS HELD AND PROVEN
================================================================================

A pass-through classification returns argv completely unchanged, deep-equal, same
order. `interactive_bash` emits arbitrary LLM-authored verbs and they must pass
through byte-identically.
    translateArgv returns `[...argv]` on the pass-through branch (src/translate.ts
    :276), never a rewrite, and never the helper. Proven by §7 above and by the
    21-case sweep at test/translate.test.ts:334-359. `rewritten` is false and
    `helperCommandLine` is undefined on every one. The translator is NOT a
    redactor: test/translate.test.ts:390-399 asserts a credential on a
    pass-through path survives verbatim, because rewriting it would be a
    behaviour change psmux never agreed to.

No flag is stripped or reordered. -P, -F, -d, -t, -n, -x, -y, -l, -c are never
altered. The emission is `[verb, ...classified.flags, ..., commandLine]`, and
`classified.flags` is the grammar-ordered head with only `-e NAME=VALUE` pairs
removed (src/grammar.ts:208-233). Asserted element-by-element and in order by
test/translate.test.ts:459-466 over all 10 fixtures, by the dedicated `-c`,
window-name, size and protected-flag assertions at :468-500, and visibly in the
full emitted arrays in §3.

new-session / new-window / split-window payloads become the PowerShell helper
invocation and nothing else.
    §3 shows each of those three emitting verb + flags + helper command line, with
    no added operand and no `--`. Their emitted length equals their input length
    (9/8/12), i.e. the payload element was replaced one-for-one and nothing was
    inserted. The suite additionally pins the emitted `--command` token vector for
    every shape (:520-527), so "the helper and nothing else" is checkable.

Credentials never appear in argv. The `-e NAME=VALUE` pairs carry
OPENCODE_SERVER_PASSWORD and travel in the process ENVIRONMENT via the
OMO_PANE_ENV_* slot mechanism, never on the helper command line.
    §5: the sentinel appears on all 5 IN argv lines and on ZERO emitted line, and
    neither does the string "OPENCODE_SERVER_PASSWORD" nor the `-e` flag itself.
    The credential travels in `envSlots` (src/translate.ts:584-594), which is the
    ONE documented-sensitive field of the result — test/translate.test.ts:869
    pins the exact key set so no new loggable field can appear by accident. Values
    are handed to the helper by POSITION as OMO_PANE_ENV_<index>, so no manifest
    and no name leaks into argv either. Delivering the slots to the psmux server is
    todo 11 / descriptor.ts work and is explicitly out of this module (see the
    comment at src/translate.ts:93-98). NOTE for todo 11: the translator strips
