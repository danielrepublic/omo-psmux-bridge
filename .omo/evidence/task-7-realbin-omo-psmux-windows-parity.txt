     >>> REAL DEFECT (reported, NOT fixed - the installed files are read-only):
     The wrapper's specified recovery path is unreachable against the real
     binary. omo-opencode-port.ps1:361-368 retries only when the child EXITS
     NON-ZERO *and* the port is no longer bindable. The real opencode, when the
     port it was told to use is already held, does not exit and does not report
     anything - it stays alive indefinitely, silently, having printed 0 bytes.
     So `WaitForExit()` at line 282 never returns, the retry condition is never
     evaluated, and the user is left with a live opencode that will never serve
     on the port the wrapper reserved for it. In this state the wrapper holds a
     reservation it can neither use nor release.
     Consequence for the plan: "close-then-exec with a single retry" is a
     correct description of the code, but it does not actually recover from a
     port stolen in the TOCTOU window when the payload is the real opencode.
     Anything stronger would need either a pre-flight bind re-check immediately
     before exec plus a bounded liveness wait, or a payload that fails fast.

  server holding them. Whoever owns the psmux state should decide whether
  ~/.psmux should be cleared as part of that work.
